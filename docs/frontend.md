# 网页前端

前端位于 `frontend/`，使用 HeroUI 3.2.6、React 19、TypeScript、Vite 8 和 Tailwind CSS 4。依赖通过 pnpm 管理，`packageManager` 固定为 `pnpm@11.0.9`，版本锁定在 `pnpm-lock.yaml`。

## 使用方式

Docker 部署后打开 `http://127.0.0.1:8000/`，输入 `config/config.yaml` 中的 `app.api_token` 登录；本地启动默认使用根目录 `config.yaml`。无需将配置文件复制到前端目录，也无需把令牌写入前端环境变量。

页面使用独立路径，可直接访问或保存为书签：

| 页面 | 路径 |
| --- | --- |
| 收件箱 | `/inbox` |
| 供应商 | `/providers` |
| 操作记录 | `/operations` |
| 系统配置 | `/settings` |

从 `/` 登录后进入 `/inbox`。切换页面时地址栏同步变化，刷新及浏览器前进、后退会保持对应页面。未登录时直接访问上述路径，会先显示登录界面，登录成功后进入原路径对应的页面。

界面支持浅色、深色主题及中英文切换，默认使用浅色与中文。偏好保存在当前浏览器的 `localStorage`，刷新和退出登录后仍保留，同源标签页会同步变化；切换立即生效，无需保存 YAML 或重启服务。语言切换同时更新页面文案、日期和时长显示，邮件原文保持不变。

网页提供：

- 选择供应商及有效期创建临时邮箱，查看异步操作结果。
- “我的邮箱”和“操作记录”每页展示 5 条，支持上一页、下一页；邮箱搜索从第一页展示匹配结果。
- 查看邮箱供应商、有效期与同步状态，复制邮箱地址。
- 邮箱到期后停止收发，已缓存的邮件摘要和正文继续只读查看；刷新页面或重启服务不会清除历史邮件。
- 在邮箱工作台点击“清除失效邮箱”，弹窗展示全部失效邮箱数量，确认后清除本地邮箱和邮件缓存。统计不受搜索和分页影响，操作记录保留；确认期间待清除集合变化时会重新统计并再次确认。
- 分页查看收件列表，读取发件人、收件人、主题与纯文本正文。
- 自动刷新本地缓存，手动刷新并查看错误提示。
- 编辑供应商和系统配置，保存到后端的 YAML 文件。
- 分别设置创建邮箱、收取邮件的并发数（`worker.create_concurrency` 默认 2、`worker.receive_concurrency` 默认 4，均为 1–32 的整数）。两类任务使用独立名额，保存后热更新；调低上限不会打断已经执行的任务。
- 退出登录并清除当前标签页中的令牌。

当前两家供应商仅支持创建和收件，页面不提供发件、远端删除或附件功能。空列表表示尚无对应数据，不会填充演示邮箱或邮件。

到期邮箱没有已缓存邮件时，页面显示“没有历史邮件”，不再提示等待新来信。邮件会保留到用户点击“清除失效邮箱”并确认。旧版本已经自动删除的邮件无法通过此行为变更恢复。

## 本地开发

需要 Python 3.12+、uv、Node.js 22.13+（可使用 24 LTS）和 pnpm 11.0.9。先按 [README](../README.md#本地启动) 安装后端依赖并初始化 `config.yaml`，保留已有数据库对应的原加密密钥。

第一个终端在项目根目录启动 API 和 Worker：

```bash
uv run python run.py --reload
```

统一入口管理一个 API 和一个 Worker。`--reload` 只对 API 启用热重载，修改 Worker 代码后需重启入口；按 Ctrl+C 会停止两者。已有手动启动的 API 或 Worker 时，先将它们停止，再使用统一入口。

第二个终端启动前端：

```bash
cd frontend
pnpm install --frozen-lockfile
pnpm dev
```

打开 `http://127.0.0.1:5173/`。Vite 将 `/v1`、`/health`、`/docs` 与 `/openapi.json` 转发到 `http://127.0.0.1:8000`，浏览器只需要访问前端开发地址。修改后端监听端口时，需同步调整 Vite 的代理目标。

统一入口不会自动启动 pnpm。需要独立管理后端进程时，启动命令见 [README](../README.md#本地启动)；只启动 API 和前端时，创建操作会等待 Worker，收件缓存也不会自动从供应商更新。

## 构建与部署

在 `frontend` 目录执行：

```bash
pnpm install --frozen-lockfile
pnpm build
```

产物写入 `frontend/dist`。在项目根目录执行 `uv run python run.py`，访问 `http://127.0.0.1:8000/` 即可使用，无需额外启动 Vite；交互 API 文档仍位于 `/docs`。

Docker 已包含前端构建阶段，执行 `docker compose up -d --build` 即可一并发布前后端。前端与 API 共用 8000 端口，部署步骤见 [Docker 部署文档](deployment.md)。修改前端源文件后需重新构建产物或镜像。

API 为 `/`、`/inbox`、`/providers`、`/operations`、`/settings` 返回同一份前端入口，支持直接访问和刷新；尾随斜杠会重定向至对应规范路径。其他未知路径仍返回 404。自行配置反向代理时，将这些页面路径也转发至 API，静态资源路径仍为 `/assets`。

## 修改配置

“供应商”页面以卡片展示各供应商的信息、能力和最长本地有效期。卡片右上角开关切换后立即将启用状态保存到 YAML，无需再次点击保存；API 随即采用新状态，Worker 在安全的任务边界切换。点击“编辑配置”打开弹窗，编辑网站入口、API 地址、请求超时、浏览器指纹、代理和最长本地有效期，再点击保存。网站入口仅用于说明，不影响供应商 API 调用；能力由后端提供，不可手动修改。

最长本地有效期对应 `max_ttl_seconds`，接受 60–31536000 的整数秒，`temp-mail-org` 默认 86400 秒，`tempmail-lol` 默认 3600 秒。该上限约束新建邮箱可选择的期限，不会延长上游实际有效期；上游到期仍优先，已有邮箱的到期时间不会随配置修改而改变。

“系统配置”页面编辑数据库路径、API 访问令牌，以及 Worker 的同步周期、操作超时和轮询间隔。

切换供应商开关或点击保存后，后端校验内容并覆盖当前使用的 YAML 文件。刷新页面会读取已保存内容，服务重启后继续使用这些配置。供应商连接参数、顺序、最长本地有效期及 Worker 周期支持热更新，常规保存无需重启。API 保存成功后立即使用新配置；Worker 在安全的任务边界切换，空闲时最多每秒检查一次。在途上游请求继续使用旧配置完成，不会因配置更新重新执行；较长的请求可能推迟 Worker 切换。

API 令牌和代理地址不回显，留空表示保留已有值；清空代理需使用明确的清除操作。修改 API 令牌保存成功后立即生效，页面返回登录界面并提示使用新令牌重新登录。加密密钥只显示配置状态，不提供查看或编辑，避免已有邮箱凭据失去访问能力。

数据库路径与加密密钥使用进程启动时的值，只有这两项变化才需重启，页面根据 `restart_required_fields` 列出具体字段。修改数据库路径不会移动数据库或迁移数据；准备好对应数据后，本地重新运行 `uv run python run.py`，Docker 执行 `docker compose restart api worker`。禁用供应商后，Worker 应用新配置时停止继续同步其邮箱，已经开始执行的操作可以完成。配置页面显示文件中保存的值，邮箱创建页的可用供应商以运行中的 API 为准。

如果其他页面或本地编辑器已修改文件，保存会提示版本冲突，不覆盖对方修改；重新加载配置后再编辑。写入失败时会显示错误，也不会热切换运行配置。手动修改为无效文件或文件不可读时，运行服务保留上一次有效配置，配置页面报告读取失败。YAML 在保存时重新格式化，文件里的注释不会保留。

## 数据与交互约定

登录成功后，API 令牌保存在当前标签页的 `sessionStorage`，刷新页面后可以继续使用，退出时清除。令牌随业务请求通过 `Authorization: Bearer` 发送；它是整个服务的访问口令，不是独立用户账户。前端静态产物不包含访问令牌、Fernet 密钥或供应商邮箱凭据。

“我的邮箱”和“操作记录”列表每页 5 条，邮件列表每页 20 条，均使用 API 分页。邮箱搜索按完整地址精确匹配；“使用中的邮箱”统计当前页。操作历史通过 `GET /v1/operations` 从 SQLite 按创建时间倒序读取，重新登录、新开标签页或重启服务后仍可查看（需使用同一个数据库）。也支持通过操作 ID 查询单条记录，并返回完整历史列表。当前标签页提交请求的 ID 仅用于跟踪进度和创建完成提示，不再决定历史列表内容；读取已完成的历史记录不会自动跳转页面。邮件正文按纯文本展示，不执行邮件中的 HTML、脚本或加载远端邮件内容。

页面每 5 秒读取本地缓存。这个刷新周期与 `worker.sync_interval_seconds` 相互独立：Worker 按配置和错误退避访问供应商，API 返回当前已缓存内容。热更新同步间隔不会立即重排已有同步计划或取消错误退避，后续同步调度采用新间隔。页面刷新成功只说明本地查询成功，应结合最后同步时间和同步错误判断上游收件情况。

创建邮箱是异步操作。提交后通过操作 ID 查询 `pending`、`running`、`succeeded`、`failed` 或 `unknown`，成功后加载真实邮箱。超时或结果为 `unknown` 时不会自动再次创建，避免重复调用供应商。提交请求遇到网络错误时会保留原参数与幂等键，刷新页面后仍可通过“继续上次创建”重试，退出登录会清除这份跟踪信息。具体状态含义见 [设计文档](design.md#6-异步写操作与幂等)。

## 检查与测试

在 `frontend` 目录执行：

```bash
pnpm check
pnpm build
pnpm exec playwright install chromium
pnpm test
```

`check` 执行 TypeScript 类型检查，`build` 验证生产构建，`test` 默认使用 Playwright Chromium 执行浏览器测试。也可使用已安装的 Chrome：`PLAYWRIGHT_CHANNEL=chrome pnpm test`（Linux/macOS）。测试使用模拟 API 响应，不创建真实供应商邮箱；`pnpm format:check` 检查前端代码格式。

后端回归测试在项目根目录执行：

```bash
uv run pytest
```
