# 配置说明

配置保存在 YAML 文件中。完整示例见 [config.example.yaml](../config.example.yaml)，首次生成配置的步骤见 [Docker 部署](deployment.md#首次部署)；源码开发见 [开发与构建](frontend.md#开发与构建)。

## 配置文件

| 运行方式 | 配置位置 |
| --- | --- |
| 本地启动 | 项目根目录 `config.yaml` |
| Docker Compose | 宿主机 `config/config.yaml` |
| 自定义路径 | 环境变量 `TEMP_MAIL_CONFIG` 指定的文件 |

API 和 Worker 必须读取同一份配置。两种部署方式的配置文件不会自动同步；相对数据库路径以配置文件所在目录为基准。业务参数只从 YAML 读取，不读取 `.env`。

`app` 和 `providers` 必填，`worker` 可省略。未知字段、重复 YAML 键和无效参数会被拒绝。

## 应用参数

| `app` 字段 | 用途 |
| --- | --- |
| `db_path` | SQLite 路径，通常为 `./data/temp-mail.db` |
| `api_token` | 至少 24 字符的服务访问令牌，网页与 API 共用 |
| `encryption_key` | Fernet 密钥，用于加密供应商凭据和待处理收件批次 |

使用已有数据库时保留原加密密钥。初始化脚本会生成新令牌和密钥，并拒绝覆盖已有配置。邮件缓存正文不做整体加密，备份时需同时保护数据库和配置文件。

## Worker 参数

以下默认值指省略字段时的行为；初始化脚本保留模板中填写的数值。

| `worker` 字段 | 默认值 | 含义 |
| --- | --- | --- |
| `sync_interval_seconds` | `15` | 同步成功后安排下一次收件的间隔，正整数秒 |
| `operation_timeout_seconds` | `300` | 恢复长时间未完成操作的超时阈值，正整数秒 |
| `poll_seconds` | `1` | 调度轮询间隔，正数秒 |
| `create_concurrency` | `2` | 操作池并发上限，1–32 的整数 |
| `receive_concurrency` | `4` | 收件池并发上限，1–32 的整数 |

当前模板将两项并发均设为 `4`。操作池执行创建及供应商支持的发送、删除；收件使用独立名额。并发限制按单个 Worker 计算，建议运行一个 Worker，通过参数调整吞吐量。

降低并发数不会中断已有任务。调整同步间隔也不会立即重排已有计划或错误退避，后续调度使用新间隔。

## 供应商参数

`providers` 以供应商 ID 为键。`auto` 按 YAML 顺序选择满足能力和有效期要求的已启用供应商；`providers: {}` 禁用全部供应商。已有邮箱始终保留原绑定。

| 字段 | 含义 |
| --- | --- |
| `enabled` | 是否启用，默认 `true` |
| `index_url` | 网站入口，仅用于展示 |
| `base_url` | 实际请求的 API 地址 |
| `timeout_seconds` | 请求超时，正数秒 |
| `impersonate` | curl_cffi 浏览器指纹，模板使用 `chrome110` |
| `proxy` | 可选的 HTTP(S) 或 SOCKS 代理 URL，支持 URL 内认证 |
| `max_ttl_seconds` | 最长本地有效期，60–31536000 的整数秒 |

`proxy` 省略、为 `null` 或空白时保留 HTTP 客户端的环境代理行为；显式代理失败不会自动改为直连。代理按供应商配置，创建和收件使用同一配置入口。

本地有效期上限不会延长上游邮箱寿命，也不会修改已有邮箱的到期时间。供应商返回到期时间时，创建结果取请求期限与上游期限中较早的时间。

供应商特有参数与协议见 [temp-mail.org](providers/temp-mail-org.md) 和 [TempMail.lol](providers/tempmail-lol.md)。

## 在线修改与热更新

在网页“供应商”中切换启用状态或编辑单个供应商；在“系统配置”中修改应用及 Worker 参数。保存会校验版本和内容，并原子替换正在使用的 YAML 文件，重启后仍生效。

| 修改内容 | 生效方式 |
| --- | --- |
| 供应商启用状态、顺序、连接参数和有效期上限 | 热更新，新任务使用新配置 |
| Worker 周期、超时和并发数 | 热更新，不中断在途任务 |
| API 令牌 | 保存成功后立即生效，需用新令牌重新登录 |
| 数据库路径、加密密钥 | 重启 API 与 Worker 后生效 |

API 保存成功后应用新配置；其他 API 进程在下次请求时检测变化，Worker 最多每秒检测一次。每个在途任务固定使用已选定的配置快照。配置热更新与 `--reload` 代码重载相互独立。

API 令牌和代理不回显，留空表示保留，代理可显式清除。加密密钥不提供网页编辑。修改数据库路径不会迁移数据库，修改密钥也不会重新加密数据；需要重启的字段由页面提示。

## 保存与异常处理

- 文件已被其他编辑者修改：拒绝覆盖，重新读取后再编辑。
- 校验或写入失败：保留原文件和运行配置。
- 手动编辑后文件无效或不可读：运行服务保留上一次有效配置，修复文件后自动恢复检测。
- 网页保存会重新格式化 YAML，不保留原注释和排版。

真实配置、令牌、代理凭据和数据库不应提交到 Git。Docker 的目录挂载与写权限要求见 [部署指南](deployment.md)。
